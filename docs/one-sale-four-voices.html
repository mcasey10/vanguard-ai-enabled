How the prompt is actually built

buildNarrationPrompt() joins a fixed 15-part system-instruction array with one space. Thirteen parts never change. Two do: the tense instruction (always prospective here — nothing has executed yet) and SEGMENT_TONE[input.segment] — the one block that actually differs across this page's four sections below. The user message is a plain JSON.stringify() of the figures ledger above, with touchpoint/tense/segment stripped out — byte-identical across all four segments, shown once here rather than repeated four times.

dev/src/server/narrationPrompt.ts real source 
// the shared assembly — same for every touchpoint and segment
export function buildNarrationPrompt(input: NarrationInput) {
  const system = [
    'You write short, factual narration for a brokerage sell/rebalance tool, addressed directly to the account holder — write as if explaining the transaction to them in conversation, never as if reciting a data structure.',
    'You may ONLY describe figures given to you in the user message below — never state, estimate, imply, or round a number that is not present verbatim in that data.',
    TENSE_INSTRUCTION[input.tense],
    // ...four more fixed formatting/framing rules...
    '"effective_rate", if present, is already expressed as a percentage number — state it with a "%" sign using that value directly (e.g. "0.26" means "0.26%", not "26%")...',
    // ...three more fixed rules (market context, Traditional IRA framing, early-withdrawal, assistive posture)...
    SEGMENT_TONE[input.segment],  ← the one part that changes below
    TOUCHPOINT_FRAMING[input.touchpoint],
    'Output prose only — no headers, no bullet points, no markdown.',
    'Respond with the final narration and nothing else: a single continuous block of text... Do not include a draft, an alternate attempt, a self-correction... — only the finished narration itself, exactly once.',  ← added D124, after a real leaked-draft response was found
  ].join(' ')

  const { touchpoint, tense, segment, ...figures } = input
  const user = JSON.stringify(figures, null, 2)
  return { system, user }
}

Segment A

Strategic optimizer — prefers data over interpretation, figure-forward brevity

One short, strictly figure-led sentence per fund, then a rollup — no explanation of why, just what happened and the resulting numbers.

SEGMENT_TONE.A = 'Segment A prefers data over interpretation and figure-forward brevity. Structure by fund count, not by a fixed sentence limit: for a SINGLE fund, write exactly ONE short, strictly figure-led sentence (~25 words) stating what happened and the resulting figures, with no explanation of why. For MULTIPLE funds, write ONE short sentence PER FUND, each following that same single-fund rule — never chain multiple funds together into one long sentence with commas/"alongside"/"plus"/"and". Example, two funds (two separate sentences, not one): "Sold $21,780.00 of VTSAX (150 shares, FIFO)... Sold $16,000.00 of VBTLX (MinTax)..." A four-fund transaction gets four short sentences, not one sentence with four clauses.'

Segment C

Reactive withdrawer — fastest credible path to executing a specific dollar amount

The shortest possible phrasing, headline figure first — and two hard content bans: no ST/LT breakdown, no per-asset-class allocation shift, ever.

Revised after publishThis section originally showed a version of the prompt with one quoted worked example — whose figures happened to be identical to this page's own canonical scenario. A live call for that exact scenario came back byte-identical to the example, and testing against genuinely different transactions found the same anchoring in 4 of 5 real calls, all echoing the example's exact phrase regardless of the real numbers. The fix below replaces the quoted example with abstract, non-copyable rules — see the note under step 3 for the full finding and what was tried before landing here.

1Coding template — real source, narrationPrompt.ts line 48 
SEGMENT_TONE.C = `Segment C (${SEGMENT_PROFILES.C.name}) is under real time pressure — goal: "${SEGMENT_PROFILES.C.goal}." Write the SHORTEST possible phrasing: one short sentence, no subordinate clauses, no explanation of reasoning, and no suggestion to pause, compare, or reconsider. State the dollar tax figure as the very first word or clause of your sentence — before naming any fund, before describing what was sold, before anything else; never lead with "Selling" or "Sold," which puts the transaction before the figure, exactly backwards. There is no single correct sentence shape for this: construct a fresh, natural-sounding way to lead with the figure each time rather than defaulting to a repeated template — two responses to two different transactions should not read as the same sentence with the numbers swapped. Two explicit content rules for this segment: (1) NEVER state the short-term and long-term gain/loss breakdown separately — state only the single net tax figure; (2) NEVER state per-asset-class allocation percentage shifts — not even a qualitative mention of an allocation effect, even as a trailing clause that otherwise reads naturally. Stop the sentence immediately after stating the fund(s) and dollar amount(s) sold — a natural-sounding sentence that ends there is not incomplete, it is the goal. What this reader needs the tool to avoid: ${SEGMENT_PROFILES.C.toolMustAvoid}.`

FindingThe version of this prompt shown when this page first published had exactly one quoted example, and that example's figures were identical to this page's own canonical scenario ("Selling $15,000 of VTSAX and $10,000 of VBTLX comes to an estimated net tax of $64.85"). Testing against genuinely different transactions (different funds, different amounts) found the same pattern in 4 of 5 real calls — each echoing the example's exact phrase "comes to an estimated net tax of" regardless of what the real transaction actually was. The same failure shape this project's Segment D wording had already been caught and fixed for once (D113), never checked for Segment C until now. Two example-based fixes (two differently-worded examples, then three) reduced but didn't eliminate it — real output settled into rotating through whichever fixed examples were offered instead of genuinely varying. The fix that actually worked removed quoted example sentences from the prompt entirely, replacing them with abstract, non-copyable rules — re-verified against five different real transactions, every one now front-loading the dollar figure (the original example never actually did, despite its own instruction saying to) and varying in real sentence structure rather than reading as one template with the numbers swapped.

Also re-verified after D124's separate leaked-draft fix (see "How the prompt is actually built" above): this exact input, run again real and cold, still comes back as one clean sentence.
